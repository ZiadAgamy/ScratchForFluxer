Docs

Build a Fluxer bot with blocks

This guide takes you from nothing to a bot that answers in your community. No coding needed, and every step says exactly where to click. Start at the top, or jump to the part you need.

How it works

You snap blocks together in your browser. {{ app_name }} turns the blocks into a Python file called main.py, and that file is your bot. Run it here with one button, or download it and run it anywhere.

  1. {{ icon("puzzle-piece") }}BlocksYou build in the editor.
  2. {{ icon("arrow-right") }}
  3. {{ icon("file-code") }}main.pyPython written for you.
  4. {{ icon("arrow-right") }}
  5. {{ icon("play") }}RunOn our runner, or on your own machine.
  6. {{ icon("arrow-right") }}
  7. {{ icon("robot") }}Your botOnline in your community.

What you need

  • {{ icon("check-circle") }}A Fluxer account with a verified email address (Fluxer asks for this before you can create a bot).
  • {{ icon("check-circle") }}A community on Fluxer where you are allowed to add bots, such as one you created.
  • {{ icon("check-circle") }}About ten minutes.
{{ icon("book-open-text") }}Words you will see{{ icon("caret-down") }}
Bot
A helper account that lives in your community and answers when something happens, such as someone typing a command.
Application
What Fluxer calls the page where a bot is set up. One application holds one bot.
Token
The bot's password. Whoever has it can control your bot, so keep it secret.
Community
A place on Fluxer with channels and members. fluxer.py calls it a guild, so you may see that word in code.
Command
A message that starts with the bot's prefix and a name, like !ping.
Prefix
The character at the start of every command. It is ! unless you change it.
Event
Something that happens: the bot comes online, a message arrives, someone joins.
Block
One puzzle piece. Blocks snap together into scripts.
Console
The panel where your running bot writes what it is doing, including errors.
Runner
The server that keeps your bots running when you press Run.
{#- ============================================================ 1. create the bot on Fluxer -#}

Step 1

Create your bot on Fluxer

First the bot has to exist on Fluxer. This part happens on Fluxer's own website, not here. Fluxer may rename or move a button from time to time. If a label below doesn't match what you see, look for the closest one.

  1. Open Fluxer and log in

    Go to {{ fluxer_web_url|replace("https://", "")|replace("http://", "") }}. Make sure your email address is verified, because Fluxer only lets verified accounts create bots.

  2. Open User Settings, then Applications

    Look for the settings (cog) icon near your name. Applications is one of the pages inside it.

  3. Create an application

    Choose a name. This will be the name people see for your bot, so pick one you like. You can change it later.

  4. Add a bot to the application

    On the application's page, add a bot. An application can have one bot.

  5. Copy the bot's token

    Press Regenerate next to the bot token and copy the new token. Fluxer may ask for your password first, and for a code from your authenticator app if you use one.

    {% call callout("warn", "The token is shown only once.") %}Copy it straight away and keep it somewhere private. If you lose it, press Regenerate again to get a new one. The old one stops working at that moment.{% endcall %}

What a token looks like

A token has two parts joined by a dot. The first part is your application's ID, which is safe to share. The second part is the secret.

1234567890123456.aBcDeFgHiJkLmNoPqRsTuVwXyZ0123456789
{{ icon("hash") }}Application ID. Safe to share. {{ icon("lock-key") }}Secret. Never share it.

That token is made up. Never paste a real one in a chat, a screenshot or a public file. If you ever do, press Regenerate on Fluxer at once.

  1. Invite the bot to your community

    Your bot has to be a member of the community before it can answer. Open this address in your browser, after swapping YOUR_APPLICATION_ID for the first part of your token (the numbers before the dot):

    {% call code("Invite link") %}https://fluxer.app/oauth2/authorize?client_id=YOUR_APPLICATION_ID&scope=bot&permissions=68608{% endcall %}

    Pick your community when Fluxer asks, then confirm. You need the Manage Community permission there (it may be called Manage Guild). The number 68608 asks for the basics: see channels, send messages and read message history. If your bot will kick, ban, time out or give roles, ask for those permissions too, and see Roles and moderation.

{% call callout("note", "Want to double-check?") %}Fluxer's own pages explain applications and invites in more detail at docs.fluxer.app.{% endcall %}
{#- ============================================================ 2. add the token -#}

Step 2

Add your bot token

Now bring the bot into {{ app_name }}. You log in with Fluxer, paste the token, and the editor opens.

  1. Log in with Fluxer

    Press Log in with Fluxer at the top right of any page. Fluxer asks you to allow the login. We only get your name and avatar. We never see your password, your email or your messages.

    {{ shot("login", "The login page of the site, with a Log in with Fluxer button.", "The login page.", width=1360, height=664) }}

  2. Press Add a bot

    You land on My bots. It is empty the first time. Press Add a bot.

    {{ shot("my-bots-empty", "The My bots page with no bots yet and an Add a bot button.", "My bots, before you have added anything.", width=1216, height=743) }}

  3. Paste the token and check it

    Paste the token into the box (1). The eye button next to it shows or hides what you typed. Then press Check token (2). We ask Fluxer if the token is real and belongs to you.

    {{ shot("add-token", "The Add a bot page with a token pasted into the box and the Check token button below it.", "Paste the token, then press Check token.", width=1216, height=680) }}

  4. Name it and save

    If the token is good, you see your bot's name and avatar. Type the name you want to see in {{ app_name }} (1). It is only used here and you can change it later. Press Save bot (2) and the editor opens.

    {{ shot("add-confirm", "The Add a bot page after the token was checked, showing the bot's name, a name box and a Save bot button.", "Fluxer confirmed the token. Give the bot a name and save.", width=1216, height=759) }}
{% call callout("tip", "Where does the token go?") %}It is encrypted before it is stored and never shown again, only its last four characters so you can tell bots apart. No block can read it, so your bot can't post it into chat by mistake. See the privacy page for the details.{% endcall %}

You can add up to {{ max_bots }} bots to one account.

A tour of the editor

The editor has three parts: the blocks on the left, the Python they write on the right, and the console at the bottom right. Everything is saved for you as you go. Look for Saved at the top.

  4. 4

Step 4

Your first bot

A new bot already knows two things. When it comes online it writes Bot is online! to the console, and when someone types !ping it answers Pong!. Let's teach it a second command, !hello, that greets people by name.

  1. Read the blocks that are already there

    Each yellow block starts a script. when the command ping is used runs when someone types the prefix and ping, and the purple block under it, reply with Pong!, answers. Click the white box that says Pong! and type something else to change the answer.

    {{ example_block({"hat": True, "parts": ["when the command", ("field", "ping"), "is used"]}, "events") }} {{ example_block({"parts": ["reply with", ("field", "Pong!")]}, "messages") }}

  2. Add a new command

    Open Events and drag when the command … is used into an empty spot. Click its white box and type hello. People will now type !hello.

  3. Add a reply under it

    Open Messages, drag reply with and drop it just under the yellow block. When the shapes line up it clicks into place.

    {{ shot("editor-palette", "The Messages family opened next to the workspace, showing purple blocks like reply with and send embed.", "Pressing a family opens its blocks. Drag the one you want out.", width=930, height=800, class="shot-narrow") }}

  4. Greet people by name

    Open Operators and drag join into the white box of reply with. Type Hello, (with a space after the comma) in the first box. Then open Message info and drag author name into the second box.

    {{ example_block({"hat": True, "parts": ["when the command", ("field", "hello"), "is used"]}, "events") }}
    reply withjoinHello, author name

    In the editor the join and author name blocks sit inside the white box, like round pieces in a hole.

  5. Check the Python

    Look at the Python tab. Your two blocks became a few lines of real code. This is the file your bot runs, and reading it is a great way to learn.

    {{ shot("editor-python", "The editor with the Python tab showing the code that the blocks write.", "The Python tab updates as you build.") }}
{% call callout("tip", "A yellow warning at the top?") %}It means a block is in the wrong place or missing a piece, for example a block that needs a message but isn't under an event. Open the Problems tab. It says what is wrong and which block it is.{% endcall %}
{#- ============================================================ 5. run -#}

Step 5

Run your bot

Make sure you invited the bot to your community (see step 1). Then:

  1. Press Run

    The status next to Console says Starting and then Running (1). Your bot shows as online in your community. In the console you see Bot is online! (3).

    {{ shot("running", "The editor while the bot runs: the console says Running and lists the bot's start-up messages.", "A running bot. The console shows what it is doing.") }}

  2. Try it in Fluxer

    Open a channel the bot can see and type !ping. The bot answers Pong!. Type !hello if you built the second command.

  3. Change something? Press Restart

    A running bot keeps the blocks it started with. After you change the blocks, press Restart to stop it and start it again with the new ones.

  4. Press Stop when you are done

    The bot goes offline (2).

What the console shows

The console is for you, not for chat. It shows the lines your write to the console blocks print, plus what the bot itself reports: that it connected, and any warnings and errors. Replies in Fluxer don't appear in it. Use the All, Warnings, Errors buttons to filter and the bin to clear it.

How long does it stay online?

  • The runner stops a bot after about {{ run_hours }} hours, so everyone gets a turn. Press Run again to go on.
  • You can run a couple of bots at the same time. If the runner is full, it says so. Try again in a little while.
  • If the runner restarts, running bots stop and don't come back by themselves. The editor says The runner no longer has this run. Press Run again.
{% call callout("tip", "Need a bot that is always online?") %}Download main.py and run it on your own computer or a server, where nothing stops it. The next two sections show how.{% endcall %}

{#- ============================================================ 7. run yourself -#}

Step 7 (optional)

Run main.py yourself

Running it yourself means you decide when it starts and stops, and it can stay online as long as the machine does. You need a computer that has Python.

On your computer

  1. Install Python

    Get Python 3.10 or newer from python.org/downloads. On Windows, tick Add python.exe to PATH in the installer.

  2. Put the files in a folder

    Unzip the folder you downloaded, or make a new folder and put main.py in it.

  3. Open a terminal in that folder

    On Windows, open the folder, click the address bar, type cmd and press Enter. On macOS, right-click the folder and choose New Terminal at Folder. On Linux, open a terminal and cd into it.

  4. Install what the bot needs

    {% call code("Terminal") %}pip install -r requirements.txt{% endcall %}

    If you only have main.py, run pip install "fluxer.py>=0.4.2,<0.5" instead. On macOS and Linux, use pip3 if pip isn't found.

  5. Give it the token and start it

    Replace paste your token here with your bot's token, then run the line for your system:

    Windows (PowerShell)

    {% call code() %}$env:FLUXER_TOKEN="paste your token here"; python main.py{% endcall %}

    Windows (Command Prompt)

    {% call code() %}set FLUXER_TOKEN=paste your token here python main.py{% endcall %}

    macOS and Linux

    {% call code() %}FLUXER_TOKEN="paste your token here" python3 main.py{% endcall %}

    You should see the lines you set up, such as Bot is online!. Try !ping in Fluxer. To stop the bot, press Ctrl + C.

{% call callout("warn", "Never put the token inside main.py.") %}Keep it in the environment variable. Anyone who sees the token can control your bot. If it leaks, press Regenerate on Fluxer and replace the token on My bots.{% endcall %}

Keep it online all the time

A bot is only online while main.py is running. Close the terminal or switch off the computer, and it goes offline. To keep it up day and night, run it on a machine that is always on, such as a small server (a VPS), a home server or a spare computer. Pick the way you like best:

{{ icon("package") }}With Docker{{ icon("caret-down") }}

Put a file called Dockerfile next to main.py and requirements.txt:

{% call code("Dockerfile") %}FROM python:3.12-slim WORKDIR /app COPY requirements.txt . RUN pip install --no-cache-dir -r requirements.txt COPY . . CMD ["python", "main.py"]{% endcall %}

Build it once, then start it so that it comes back after a restart:

{% call code("Terminal") %}docker build -t my-fluxer-bot . docker run -d --name my-fluxer-bot --restart unless-stopped -e FLUXER_TOKEN="paste your token here" my-fluxer-bot{% endcall %}

See what the bot says with docker logs -f my-fluxer-bot. Many hosting panels that run containers have a box for environment variables. Add FLUXER_TOKEN there.

{{ icon("linux-logo") }}As a service on Linux (systemd){{ icon("caret-down") }}

Store the token in a private file, so it isn't in the service file:

{% call code("Terminal") %}echo 'FLUXER_TOKEN=paste your token here' > ~/mybot/.env chmod 600 ~/mybot/.env{% endcall %}

Then create /etc/systemd/system/mybot.service:

{% call code("mybot.service") %}[Unit] Description=My Fluxer bot After=network-online.target [Service] WorkingDirectory=/home/you/mybot EnvironmentFile=/home/you/mybot/.env ExecStart=/usr/bin/python3 main.py Restart=always User=you [Install] WantedBy=multi-user.target{% endcall %}

Start it, and make it start with the machine:

{% call code("Terminal") %}sudo systemctl enable --now mybot sudo journalctl -u mybot -f{% endcall %}
{{ icon("cloud") }}On a hosting service that runs Python{{ icon("caret-down") }}

Most services that run Python programs (or containers) work the same way:

  1. Upload main.py and requirements.txt.
  2. Set the start command to python main.py.
  3. Add an environment variable called FLUXER_TOKEN with your token as its value.
  4. Start it, and read its logs to see Bot is online!.

Choose a service that keeps the program running all the time. Some free plans put programs to sleep, which would take your bot offline.

{% call callout("note", "Edited main.py by hand?") %}You can, and it runs fine. But changes you make in the file don't come back into the blocks. If you keep building with blocks, download a fresh copy each time.{% endcall %}

{#- ============================================================ troubleshooting -#}

Help

Troubleshooting

Something not working? Find what you see below.

Check token says the token isn't valid
  • Copy the whole token, including the number, the dot and everything after it. No spaces at the start or the end.
  • If you pressed Regenerate since you copied it, the old token is dead. Copy the newest one.
  • If you aren't sure, press Regenerate on Fluxer again and paste the fresh token.
It says the bot doesn't belong to my account

You can only add a bot that your Fluxer account owns. Log in here with the same Fluxer account that created the application. Check the name at the top right of the page.

The bot is running but doesn't answer in Fluxer
  • Did you invite it? The bot has to be a member of the community. See the invite link in step 1.
  • Can it see the channel? The bot needs to see the channel and be allowed to send messages in it. Check the channel's permissions.
  • Typed it right? Start with the prefix. If the prefix is ! and the block says ping, people type !ping. Don't type the prefix inside the block's box.
  • Did you press Restart? A running bot doesn't pick up new blocks until you do.
  • Look at the console. Errors show up there in red.
The Run button doesn't work, or says that running bots isn't switched on

The runner, the server that keeps bots online, isn't reachable right now. Try again in a few minutes. In the meantime you can download main.py and run it yourself, which doesn't need the runner at all.

My bot went offline by itself
  • The runner stops a bot after about {{ run_hours }} hours. Press Run again.
  • If the runner was restarted, every running bot stops. The editor says The runner no longer has this run. Press Run.
  • If you replaced or regenerated the token, the old one stops working at once. Replace it on My bots.
  • For a bot that must never go offline, run it yourself.
Roles, kick, ban and timeout blocks don't work
  • The bot needs the matching permission in your community: Manage Roles to give or take roles, Kick Members, Ban Members, or the timeout permission.
  • A bot can only manage roles that are lower than its own highest role. In the community's role settings, drag the bot's role above the ones it should give.
  • A bot can't act on the owner of the community, or on someone whose highest role is above its own.
  • The blocks print Moderation failed in the console, with the reason, instead of crashing. Read that line.
  • Think about who can type the command. A command that bans people is dangerous if anyone can use it. Add an if block that checks for a staff role first.
Blocks won't snap together
  • Yellow event blocks have no notch on top, so nothing can go above them. Other blocks go under them.
  • Round blocks go into white boxes, not under other blocks.
  • Move the block until a preview of where it will click appears, then let go.
  • Dropped one in the wrong place? Undo with Ctrl + Z.
The Python file won't download

Open the Problems tab (or the yellow pill at the top). Fix each item and the download works again.

The login says "Your login session expired or didn't match"

Your browser blocked the cookie that logging in needs, or you opened the site at a different address than the one you started on. Allow cookies for this site, open it at {{ site|replace("https://", "")|replace("http://", "") }}, and log in again.

My token was leaked

Don't panic. Press Regenerate next to the bot token on Fluxer. The leaked token stops working at once. Then paste the new token with Replace token on My bots, and update it wherever else you run the bot.

python isn't recognised, or pip isn't found

Python isn't installed, or isn't on your PATH. Reinstall it from python.org and tick Add python.exe to PATH. On Windows you can also try py main.py and py -m pip install -r requirements.txt. On macOS and Linux use python3 and pip3.

KeyError: 'FLUXER_TOKEN'

You started main.py without setting the token first. Set FLUXER_TOKEN in the same terminal window, right before starting the bot, as shown in Run main.py yourself. A new terminal window forgets it.

{#- ============================================================ faq -#}

Questions

Do I need to know how to code?

No. Blocks do the coding for you. And if you want to learn, the Python tab shows the real code that each block writes.

Is my token safe?

It is encrypted before it is stored, it is never sent back to your browser, and no block can read it. When your bot runs, it is sent over HTTPS to the runner and kept in memory only. The privacy page lists everything we keep.

Can I use the same bot on more than one community?

Yes. Invite it to each community with the invite link. One bot runs one set of blocks everywhere it has been invited.

Will my variables and lists be remembered?

Only while the bot runs. When it stops or restarts, they start from their first value again. For anything that must survive a restart, keep it in a JSON file you read with the JSON blocks.

Can I make a block that isn't in the list?

Not yet. The blocks are fixed on purpose, which is what lets us check that every bot is safe to run. If you wish a block existed, tell us{% if community_url %} in the community server{% endif %}.
